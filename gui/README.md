# forgeai GUI

[Wails](https://wails.io) desktop client of forgeai. It talks to the Kubernetes API directly through a kubeconfig context (`$KUBECONFIG` or `~/.kube/config`) and a forgeai project namespace; the operator does the rest. See the top-level README for the views and the objects they manage.

| Path | Description |
|---|---|
| `main.go` | Wails entry point |
| `app/` | Go backend bound to the frontend, split by area: connection (`conn.go`), jobs (`jobs.go`), templates (`templates.go`), volumes (`volumes.go`), file server (`files.go`), registry images (`images.go`), instance types and quota (`cluster.go`), project administration (`admin.go`), cluster dependencies (`deps.go`), the forgeai operator's Helm install (`chart.go`) |
| `app/deps/` | Install manifests of Kueue, Trainer v2 and agent-sandbox at the pinned versions, embedded in the binary; `manifest.json` records each digest. Refresh with `make gui-deps` (`hack/gui-deps.sh`) |
| `frontend/` | React + TypeScript (Vite); `wailsjs/` is generated by Wails |
| `DESIGN.md` | UI design system |

## Live development

```sh
make gui-dev    # from the repository root
```

This runs a Vite dev server with hot reload. A browser dev server on http://localhost:34115 also exposes the Go methods.

Do not run `wails dev` in this directory directly. It builds its debug binary into `build/bin/forgeai.app` and, on exit, deletes only `Contents/MacOS/forgeai`, leaving a bundle without an executable behind; launching it then reports that forgeai is damaged or incomplete until it is rebuilt. `make gui-dev` (via `hack/gui-dev.sh`) moves the packaged bundle aside for the dev session and restores it afterwards. If you did run `wails dev` directly, `make gui` recreates the app.

## Building

```sh
make gui    # from the repository root: wails build -clean -> build/bin/forgeai.app
```

The wails CLI must be built with `golang.org/x/tools >= v0.52` and be first on `PATH`.

## Releases

Pushing a `v<major>.<minor>.<patch>` tag runs `.github/workflows/gui-release.yml`. It builds the client for macOS (universal), Windows (x64) and Linux (x64) and publishes them as a GitHub release with the installers and `SHA256SUMS.txt` attached:

```sh
git tag v0.1.0
git push origin v0.1.0
```

The tag's version becomes the app version (`info.productVersion` in `wails.json`, set by CI) and the installer file names. Pull requests that touch the GUI build the same installers as workflow artifacts without publishing them. The CI build also pins the wails CLI to v2.16.0 with `golang.org/x/tools` v0.52.0, as described above.

## Updates

The client compares its version with the latest GitHub release (`app.Version`, set by the release workflow with `-ldflags`; a local build is `dev` and never offers an update). Six hours after the start, and on each start, it asks GitHub for the latest release; when that is newer, an "Update version" button floats at the foot of the sidebar. The application menu shows the running version under "About forgeai" and has "Check for Updates…" right below it (in the menu named after the app on macOS, in a Help menu on Windows and Linux); it checks at once and reports the outcome in the window. Installing the update downloads the release file for the platform, checks it against `SHA256SUMS.txt`, replaces the running app and restarts it:

- macOS: the `.dmg` is mounted and its `forgeai.app` replaces the running bundle.
- Windows: an installed client runs the `-setup.exe` silently (it asks for administrator rights, since the installer is per machine by default); the portable client replaces its executable.
- Linux: the `.tar.gz` binary replaces the running executable. A `.deb` install under `/usr` needs root, so the update fails there; install the new `.deb` instead.

The update code is in `app/update.go`. Only the macOS path has been run end to end.

Installers are not code-signed or notarized. `hack/gui-package.sh <version> <darwin|windows|linux>` packages the output of `wails build` the way CI does; the release notes text is in `hack/gui-release-notes.md`.

The Dependencies view installs the forgeai operator from the Helm chart `oci://ghcr.io/wutz/charts/forgeai` at the version pinned as `forgeaiChartVersion` in `app/chart.go`. Bump that constant in the same change that tags the release publishing the new chart version. The chart and operator image packages on ghcr.io must be public, because the GUI pulls the chart without credentials.

# forgeai GUI

[Wails](https://wails.io) desktop client of forgeai. It talks to the Kubernetes API directly through a kubeconfig context (`$KUBECONFIG` or `~/.kube/config`) and a forgeai project namespace; the operator does the rest. See the top-level README for the views and the objects they manage.

| Path | Description |
|---|---|
| `main.go` | Wails entry point |
| `app/` | Go backend bound to the frontend, split by area: connection (`conn.go`), jobs (`jobs.go`), templates (`templates.go`), volumes (`volumes.go`), file server (`files.go`), registry images (`images.go`), instance types and quota (`cluster.go`), project administration (`admin.go`) |
| `frontend/` | React + TypeScript (Vite); `wailsjs/` is generated by Wails |
| `DESIGN.md` | UI design system |

## Live development

```sh
make gui-dev    # from the repository root
```

This runs a Vite dev server with hot reload. A browser dev server on http://localhost:34115 also exposes the Go methods.

Do not run `wails dev` in this directory directly. It builds its debug binary into `build/bin/forgeai.app` and, on exit, deletes only `Contents/MacOS/forgeai`, leaving a bundle without an executable behind; launching it then reports that forgeai is damaged or incomplete until it is rebuilt. `make gui-dev` (via `hack/gui-dev.sh`) moves the packaged bundle aside for the dev session and restores it afterwards. If you did run `wails dev` directly, `make gui` recreates the app.

## Building

```sh
make gui    # from the repository root: wails build -clean -> build/bin/forgeai.app
```

The wails CLI must be built with `golang.org/x/tools >= v0.52` and be first on `PATH`.
